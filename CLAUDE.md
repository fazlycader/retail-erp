# Retail ERP: project guide

Multi-location retail and wholesale system: a **head office warehouse plus showrooms**, each with its own stock, sales, purchasing and documents, run by staff who may work at several locations. Built by MVRK+; it reuses the proven building blocks of MVRK+ RMS (`~/websites/restaurant-pos`).

It's built in steps. **Only build what the current step asks for.** Keep this file updated at the end of every step.

## Hosting constraints (read before adding anything)

Same target as RMS: **shared hosting** (PHP 8.4 + MySQL, cron, SSH, Composer).

- No Redis, Supervisor, long-running processes or WebSocket server. Queue, cache and sessions use `database`.
- Live screens use **polling** (`useStaffSync` + `App\Support\SyncVersion`).
- Node never runs on the server; assets are built before upload.
- Composer's platform is pinned to PHP 8.4 (`config.platform.php` = 8.4.99) so `composer.lock` installs on the host.

## Stack

- Laravel 13, PHP 8.4+, MySQL 8 (tests use in-memory SQLite, plus one MySQL concurrency test)
- Inertia.js 2 + Vue 3 (`<script setup>`, plain JS) + Tailwind CSS 4 (configured in `resources/css/app.css`, brand colour = indigo, no tailwind.config.js)
- Laravel Breeze (Inertia/Vue) for auth; **public registration removed**, no account self-delete
- intervention/image v4 (GD) for logos/photos
- No axios: JSON calls use `@/lib/http` (fetch + XSRF cookie)
- Pest 5, Pint
- Timezone **fixed** `Asia/Colombo` (`config/app.php`), currency `LKR` (`config('app.currency')`)

## Conventions

### Money, percentages, quantities
- **Money is integer cents** (`*_cents` or a plain name with `App\Casts\MoneyCast`). Never floats or `decimal` columns. `App\Support\Money` (`fromCents`, `fromDecimal('1250.50')`, `add/subtract/multiply`, `format()` → `LKR 1,250.50`); helper `money(125050)`. Front end `@/lib/money` formats only; totals are server-side.
- **Percentages are basis points** (`_bp` columns): 18% = 1800. `App\Support\BasisPoints::fromPercent()/toPercent()`.
- **Quantities are integer milli-units** (`App\Support\Quantity`, SCALE 1000): 1.25 kg = 1250, 3 pcs = 3000. `parse('1.25')`, `toDecimal()`, `format(1250, 'kg')`, `fromUnits(3)`, `times($milli, $unitCents)` = line value in cents, rounded half up.

### Locations (the core of this system)
- `locations`: `name`, `code` (unique, uppercase, ≤10, used on documents and lists), `type` (`App\Enums\LocationType`: warehouse/showroom), `address`, `phone` (+94…), `is_active`. Every location gets a `location_settings` row on create.
- Users: `home_location_id` (nullable only for admins) + `location_user` pivot for extra locations. **The home location is always in the pivot too**; set both with `$user->assignLocations($homeId, $extraIds, $keepIds)`. `$user->locationIds()` (memoised; reset by `assignLocations`/`refresh`), `$user->worksAt($location)` (admins: always), `User::atLocation($id)` scope (home or extra).
- `Location::accessibleTo($user)`: active locations the user may work at (admins: every active one).
- **Current location** (`App\Support\CurrentLocation`, request-scoped): picked in the top-bar switcher, stored in session key `current_location` (an id or `"all"`). Middleware `ResolveCurrentLocation` (web group) checks it on every request: a location the user no longer has, or an inactive one, falls back to the home location, then their first location. Non-admins with no active location get a 403 (only logout works).
  - **"All locations"** (admins only) applies on routes with the `all-locations` middleware (a no-op marker, `AllowsAllLocations`). Navigation modules opt in with `'all_locations' => true`; `Navigation::middleware($key)` adds it. On other pages an admin in "all" mode works at their home location for that request, and the choice is kept for the next "all" page.
  - API: `CurrentLocation::get()` (null = all), `id()`, `isAll()`, `accessible()`, `visibleIdsFor($user)` (null = no restriction).
  - Switch: `POST /location {location: id|"all"}` (`LocationSwitchController`); anything the user doesn't have → 403.
  - Shared to Vue: `location` (`{id, name, code, type}` or null), `locations` (switcher list), `locationScope` (`{all, can_all}`). `Components/LocationSwitcher.vue` in `AdminLayout`.
- **Location-specific tables** get a `location_id` FK and their model uses `App\Models\Concerns\BelongsToLocation`: fills `location_id` on create from the current location (else the user's home location), `->forLocation()` (current; "all" = every location the user can see) and `->visibleTo($user)`. Pass a location explicitly in jobs/commands.

- **Staff rules** (`UserPolicy`, `StaffController`): admins manage everyone. Managers manage non-admin staff whose **home location** is one of the manager's locations, and can only assign their own locations (links to other locations are kept untouched when they edit). Nobody deactivates themselves or changes their own role. Staff list = staff linked to the current location (admins: also all).
- **Locations** (`LocationPolicy`): admins create/deactivate (never the last active one); managers edit details + settings of locations they work at.
- Inactive users can't log in (`LoginRequest` uses `attemptWhen`), and `EnsureUserIsActive` signs out a user deactivated mid-session.
- **PINs**: optional hashed 4–6 digits (`pin` cast `hashed`), not unique. `User::attemptPin($pin, $context)`: 10 failures in 15 min lock the PIN for 15 min (`pin_failed_attempts`, `pin_last_failed_at`, `pin_locked_until`, audit `user.pin_locked`); managers unlock via `staff.unlock-pin`.
- **Manager approval** (`App\Support\ManagerApproval::verify($actor, $locationId, $approverId, $pin, $action, $subject, $what)`): approver = active admin, or manager who works at that location, with the right PIN; 5 tries/min per actor; refusals throw `ApprovalRefused` (`toResponse()` = JSON 422) and audit `{action}_denied`. `approvers($locationId)` for the picker. No caller yet (sales/returns will use it).
- **Shared terminals** (`App\Support\Terminal`, `Auth\TerminalController`): a manager turns a device into a terminal **for the current location** (encrypted `shared_terminal` cookie, 1 year; user menu). `/terminal` lists active staff with a PIN who work there (and admins); `POST /terminal/unlock` (throttle `pin-login`) signs them in at that location. Lock button + auto-lock after `location_settings.auto_lock_minutes`.

### Product catalog & import
- Catalog tables are shared across all locations (`2026_10_24_000000_create_catalog_tables.php`): `categories` (nested up to 3 levels via `CategoryTree`), `attributes` + `attribute_values` (with SKU short code, hex swatch colour or swatch image), `products` (`App\Enums\ProductType`: `stock`, `made_to_order`, `service`; rich text description sanitised via `App\Support\RichText`; W×D×H mm, weight g, assembly/delivery flags, warranty months with category inheritance, serialized flag, online/SEO fields, tags, soft deletes), `product_variants` (unique SKU & barcode across all variants including soft-deleted ones; blank barcode generates Code 128 `20xxxxxxxxxx` via `App\Support\Barcode`; `price`, `min_price`, `online_price`, `average_cost`, `last_cost` in cents; `reorder_level`, `reorder_qty` in milli-units; a product without options still has one default variant with `combination_key = ''`), `product_images` (WebP + thumbnail via `ImageUploader`, optional variant link, sortable), `product_supplier` (`suppliers` table created with `name` for step 4), `price_change_logs` (written by `ProductVariant` model events on create/update of `price`, `min_price`, `online_price`, with `source`: `form`, `bulk`, `import`).
- Services in `App\Services\Catalog`: `CategoryTree`, `VariantGenerator` (cartesian combinations preserving existing variants), `ProductService` (transactional save + validation), `BulkPriceChange` (preview + apply % change with rounding and min-price guard), `PriceFloor` (`authorise()` requires manager override or PIN when selling below `min_price`), and `Import\ImportService` (`ImportFields`, `ImportRowChecker`, `ImportWriter`, `RunCatalogImportStep` job batching for large XLSX/CSV files: upload → column mapping → dry run report → commit matching by SKU, never deleting).
- Gates: `edit-catalog` (admin, or manager when `company_settings.managers_edit_catalog` is on), `view-cost` (admin, manager, accountant — cost props are omitted from Inertia payloads for sales/cashier and storekeeper roles).

### Inventory, transfers & stock counts
- Inventory tables (`2026_10_25_000000_create_inventory_tables.php`): `stock_levels` (unique `product_variant_id, location_id`, `on_hand`, `reserved`, `sync_version`), `stock_movements` (immutable ledger — updating or deleting throws `LogicException`; `App\Enums\MovementType`, signed `quantity` in milli-units, `balance_after`, `unit_cost` in cents, morph `reference`, optional `stock_unit_id`, `business_date`), `stock_units` (`is_serialized` tracking with `serial_number`, `App\Enums\StockUnitStatus`, `App\Enums\StockUnitCondition`: `new`, `display`, `damaged`), `stock_reservations` (`App\Enums\ReservationStatus`), `stock_adjustments` + `stock_adjustment_lines` (`App\Enums\AdjustmentReason`; adjustments above `company_settings.adjustment_approval_value` require manager PIN via `ManagerApproval`), `transfers` + `transfer_lines` (`App\Enums\TransferStatus`: `draft` → `requested` → `dispatched` → `received` | `partially_received` → `closed` | `cancelled`; short receipts resolved by manager as `write_off` or `return_to_source`), `stock_counts` + `stock_count_lines` (`App\Enums\StockCountScope`, `App\Enums\StockCountStatus`, frozen `system_qty`, `blind` mode, barcode scanner `+1` entry, manager posting), and `opening_stock_imports` + `opening_stock_import_rows` (XLSX/CSV per location with dry run before commit).
- Services in `App\Services\Inventory`: `StockService` (`move()`, `moveMany()` — the ONLY writer of `stock_levels` and `stock_movements`; locks levels in `(location_id ASC, product_variant_id ASC)` order using MySQL `INSERT … ON DUPLICATE KEY UPDATE id = LAST_INSERT_ID(id)` + `SELECT … FOR UPDATE` to prevent deadlocks; updates weighted average cost on `opening` and `purchase_receipt`; refuses negative stock when `allow_negative_stock` is off via `InsufficientStock`), `ReservationService` (`reserve()`, `release()`, `fulfil()`), `AdjustmentService`, `TransferService`, `StockCountService`, `OpeningStockImportService`, and `stock:verify` Artisan command (`App\Console\Commands\StockVerify`).

### Documents and counters
- `App\Enums\DocumentType`: invoice INV, quotation QUO, sales_return SRN, receipt RCT, credit_note CN, refund RFD, purchase_order PO, grn GRN, supplier_return SUR, transfer TRF, adjustment ADJ. Prefix: `CompanySetting::current()->prefixFor($type)`. Prefixes are unique and alphanumeric.
- **Gap-free numbers**: `App\Support\Counter::next($type, $scope)` on the `counters` table (unique `type, scope`), inside the document's transaction: a rollback gives the number back. MySQL path: a non-locking existence read, then `UPDATE … SET last_number = LAST_INSERT_ID(last_number + 1)` on the existing row (record lock only); the first number of a scope uses `INSERT … ON DUPLICATE KEY UPDATE`. Never upsert an existing row: the upsert gap-locks the end of the table and deadlocks against other upserts in the same transaction (same rule in `StockService::lockLevel`). Top-level sale transactions retry deadlocks (`DB::transaction(…, 3)`) for the one-time first-insert race. Verified by `CounterTest` with 8 parallel processes on MySQL (400 attempts, every 5th rolled back → exactly 1…320). Pick the scope per document, e.g. `"location:{id}"` or `"location:{id}:{year}"`.
- **Business day** (`App\Support\BusinessDay`): `for($at, $cutoff)`, `current($locationId)` (uses the location's cutoff), `window($date, $cutoff)` → UTC start/end. Every future `business_date` column uses it.

### POS, payments, invoices & returns (Step 6)
- Tables (`2026_10_28_000000_create_payment_tables.php`): `payment_methods` (seeded in the migration: cash, card, bank_transfer, cheque, lankaqr, online, credit_note, other; `requires_reference`, `opens_cash_drawer`, `is_active`; `App\Enums\PaymentMethodCode`), `payments` (receipts `RCT-{LOC}-000001`, order or on-account, `amount` applied + `tendered`/`change_given` for cash, cheque fields + `cheque_status` `App\Enums\ChequeStatus` pending → deposited → cleared | bounced, `credit_note_id`, `shift_id` (step 7), `business_date`, `status` completed | voided, `share_token`), `credit_notes` (`CN-…`, `amount`/`remaining`, `expires_on` from `company_settings.credit_note_expiry_days`, status open | used | voided), `refunds` (`RFD-…`, against a return or a credit note, method, reason, approver, `shift_id`; cash refunds need an open shift), `sales_returns` + `sales_return_lines` (`SRN-…`, condition resaleable | display | damaged, restock location, outcome refund | credit_note | exchange, `exchange_order_id`), `pos_held_carts` (client cart JSON per location), Laravel `notifications`. `sales_orders` gained `share_token`, `returned_total`, `refunded_total`; `company_settings` gained `return_days` (7) and `credit_note_expiry_days` (365, 0 = never), both on the settings page.
- Money on an order: `paid_amount` = counted payments (completed and not bounced, `Payment::counted()`); kept = paid − `refunded_total`; `netTotal()` = grand total − `returned_total`; `balance_due` = net − kept. `PaymentService::refresh($order)` recomputes paid, balance, `payment_status` and `advance_pending`.
- `Sales\PaymentService`: `receive()` locks the order first, refuses anything above the balance due except cash (excess = change), requires a reference where the method does, cheque bank/number/date, and a usable credit note of the same customer; `void()` needs a manager (others give a manager PIN; checked before the transaction so a refused PIN stays audited) and restores credit notes; `setChequeStatus()` — a bounce reverses the payment, reopens the balance, notifies the location's managers and admins (`Notifications\ChequeBounced`, database + mail) and is audited.
- `Sales\ReturnService::process()`: quantities up to fulfilled − returned (services: ordered − returned); after `return_days` a manager approves; stock comes back as `sale_return` at the chosen location (serialized units get the condition), damaged goods are then written off as `damage`; only what was paid beyond the new net total is settled (refund, credit note, or exchange = credit note that links `exchange_order_id` when it pays the new sale); the rest just lowers the balance.
- `Sales\CreditNoteService` (issue, manager-approved refund, `recordRefund`). Cancelling a paid order now puts what was paid on a credit note. `SalesOrderService::removeLine()` removes an unfulfilled line from a confirmed order and reprices it (never below what was paid); `complete()` closes a paid + fulfilled order. Walk-in cash & carry sales confirm without a customer.
- `Sales\PosCheckoutService::checkout($cart, $payments, $actor)`: one transaction — save, confirm (invoice number), payments, and for cash & carry require full payment, fulfil and complete. Any failure rolls back the invoice number too.
- POS (`/pos`, `PosController`, `Pages/Admin/Pos/Index.vue`, current location): search/scan (`pos.products`: exact barcode/SKU adds straight to the cart; availability here and at other locations; `cost_cents` only with `view-cost`), category browse, customer by phone with inline create (`customers.lookup`/`customers.store` JSON), server-side cart totals (`pos.price`, also says whether a manager PIN will be needed — no audit writes), full-screen pay pad (split methods, quick cash, change, cheque/credit note fields), approval dialog, hold/resume (`pos.held.*`), result screen with print/WhatsApp/SMS. The shared-terminal lock comes from `AdminLayout`.
- Documents: `App\Support\SalesDocuments` renders A4 PDFs with dompdf from `resources/views/documents/*` (invoice, receipt, credit note, delivery note; company logo, location details, VAT no., terms, QR to the digital copy). "Tax Invoice" only when VAT registered (`invoiceTitle()`). Thermal 80 mm receipt: `pos.receipt` (`documents/thermal.blade.php`, `@page 80mm`, `?print=1` auto-prints). Public digital copy: `/doc/{token}` and `/doc/{token}/pdf` (`DocumentController`, 40-char tokens on orders, payments, credit notes; throttled, noindex). `PosController::shareLinks()` builds wa.me / sms: links. Cash drawer kick is out of scope (later: RMS print agent).
- Screens under Sales: Payments (`sales.payments.*`, cheque actions with gate `manage-cheques` = admin, manager, accountant), Returns, Credit notes (refund), and on the order page (`Partials/OrderMoney.vue`) take payment, void, cheque status, return items, print & share, remove unpaid line.

### Shifts & cash (Step 7, ported from RMS step 8)
- Tables (`2026_10_29_000000_create_cash_tables.php`): `registers` (per location, unique name; every location gets "Main Counter" on create), `cash_movement_categories` (shared by all locations, seeded, `applies_to` any | pay_in | pay_out | cash_drop), `shifts` (location, register, cashier, business date, `App\Enums\ShiftStatus` open → closed (variance waiting for approval) → approved; one open per register and per cashier via unique `open_register_id` / `open_user_id`; float + denomination counts, expected/counted/variance, terminal totals, force-close reason, approval, **`z_report` frozen at close**), `cash_movements` (`App\Enums\CashMovementType` pay_in | pay_out | cash_drop, category snapshot, approver, `bank_deposit_id`), `bank_deposits` (source safe | shift, slip reference, bank account, cash + cheques), `business_days` (model `DayClose`, per location, frozen report, accepted warnings). `payments.bank_deposit_id`, `sales_orders.invoice_printed_at` (set by the A4 invoice and the 80 mm receipt). `company_settings`: `require_shift_for_payments` (on), `blind_close` (on), `variance_approval_threshold` (Rs. 500), `payout_approval_threshold` (Rs. 5,000), edited by admins on `/cash/setup`.
- A device remembers its register in the encrypted `pos_register` cookie (`App\Support\DeviceRegister::id($request, $locationId)` / `current()`; only a register at that location counts; automatic when the location has one active register).
- `App\Services\Cash\ShiftService` (open, movement, close, approve; manager PINs are verified by the caller before the transaction). `forTransaction($user, $locationId, $registerId)` = the user's own open shift **at that location**, else the device register's open shift there. `PaymentService` and `CreditNoteService::recordRefund` link `shift_id` and, with `require_shift_for_payments`, refuse payments (any method) and **cash** refunds without one (`CashActionRefused` reason `shift_required`; POS shows a banner and the message).
- **Expected cash** (`CashCalculator::expected`) = float + cash payments (amount, already net of change, not voided) + pay-ins − cash refunds − pay-outs − cash drops. Step 12 adds cash handed over by drivers. Pay-outs above the threshold need a manager PIN; drops/pay-outs can't exceed the drawer.
- Close: blind count (cashiers never see expected until they've counted; managers always do), |variance| ≤ threshold → approved, else closed until a manager approves (or approves at close with PIN + note). Force-close = a manager closes with their count and a reason. X-report live, Z-report stored (`ShiftReport::build`, `blind()`), both printable on 80 mm (`cash.shifts.print`, `documents/shift-report`); movement slips to sign (`cash.movements.slip`). No print agent / drawer kick (later: RMS print agent).
- **Bank deposits** (`BankDepositService`, `/cash/deposits`, managers): cash from the safe (safe = drops not sent straight to the bank − earlier safe deposits) or from an open shift (recorded as a "Bank deposit" cash drop on it), plus pending cheques in bulk (each marked deposited via `PaymentService::setChequeStatus`).
- **End of day** (`DayCloseService`, `DayReport`, `/cash/end-of-day`, managers, current location): open shifts **block**; shifts waiting for approval, unprinted invoices, pending cheques dated on/before the day, and transfers dispatched to this location **warn** (confirm to continue). Close freezes the report and locks the day. **Locked day** (`App\Support\DayLock::guard`): voiding its payments, removing order lines or cancelling its orders is admin-only and audited `day.locked_edit`; no new shift opens on a closed day.
- Permissions: cashiers — own shift (open, movements, X-report, close, view/print own); managers/admins — the location's shifts (list, approve, force-close), registers & categories, deposits, end of day; admins — shift settings. Everything is scoped to the location: a Kandy cashier or manager can't see, print, approve or close a Galle shift.
- Screens: `Pages/Admin/Cash/{Current,Shifts,Show,Setup,Deposits,EndOfDay}` with `Partials/CashNav`, `Components/Cash/{DenominationCounter,ManagerPin}`, `lib/time.js`.

### Owner dashboard & reports (Step 8, ported from RMS)
- Tables (`2026_10_30_000000_create_report_tables.php`): `daily_location_summaries` (one row per location per business date: invoices, gross, discounts, sales, VAT, delivery, revenue ex VAT, cost, returns (count, value, revenue ex VAT, cost), payments, collected, refunds, cancelled; JSON `by_method`, `by_channel`, `by_salesperson`), `daily_variant_summaries` (per location, date and variant or custom item: qty, revenue, revenue ex VAT, discounts, cost, returned qty/value/cost), `report_exports`, `daily_report_sends` (one per business date). `company_settings`: `managers_see_profit` (off), `report_emails` (JSON), `daily_email_time` (07:00) on the company settings page.
- **Definitions** (`Reports\SalesData`, live): sales = invoices (confirmed, not cancelled) on their business date at the selling location; revenue ex VAT = item `line_total − tax_cents`; cost = qty × `unit_cost_snapshot`; gross profit = revenue ex VAT − cost, net of returns (counted on the return's date, proportional value and cost); collected = payments not voided on the date; refunds on the date.
- `SummaryBuilder` builds one location-day from those same queries — at end of day (`DayCloseService::close`), hourly for the last 3 days (`reports:summarize`, also `--from/--to`). `SalesReader` reads summary rows for past days and calculates today/missing days live, per location; results are identical (tested).
- `ReportRange` (location ids + dates, presets, `previous()` = same weekday last week for one day, `scope()`, `window()` for timestamp-only records), `ReportScope` (admins: every active location; others: their locations; `?location=all|id`, default the current location), `ReportCatalog` (titles, groups, `max_days`, `snapshot`, `profit`), `ReportBuilder` (sales, products, profit, payments, discounts & approvals, returns, quotation conversion) + `StockReports` (stock on hand & valuation at average cost, low stock, slow-moving/dead stock with `?days=N`, stock movement summary, transfers, purchases by supplier, cheques), shared `Concerns\BuildsReports` (`card`, `table`; **table rows carry only their columns' keys**). `ReportExporter` (CSV/XLSX, openspout; money in rupees, quantities in units), > 5,000 rows → `ExportReport` job + Downloads; `reports.print` A4 print view.
- **Profit**: gate `view-profit` = admin, accountant, or manager when `managers_see_profit`. The profit report needs it; elsewhere profit cards, columns and row fields are left out (not hidden) without it, including the dashboard.
- **Dashboard** (`OwnerDashboard`, admins/managers/accountants; others keep the welcome): per location today vs the same day last week (net sales, collected, cash collected, gross profit if allowed), open orders by status, deliveries waiting, low stock count, transfers in transit, pending cheques, quotations to follow up, shift variances waiting.
- **Daily email** (`DailyOwnerReport` → `SendDailyReport` → `DailyReportMail`, `emails/daily-report.blade.php`): yesterday per location vs last week, top items, cash variances, low stock now. Sent once per date: when the last location that traded closes its day, else by `reports:daily-email` at `daily_email_time` (lists the locations not closed).
- Scheduler (`routes/console.php`, one cron `schedule:run` every minute): `queue:work --stop-when-empty`, `reports:summarize` hourly, `reports:daily-email` every 5 minutes, `reports:prune-exports` daily.
- Screens: `Pages/Admin/Reports/{Index,Show}`, `Components/Reports/{ReportChart,ReportTable}` (Chart.js loaded on demand), `lib/format.js`, owner section in `Pages/Admin/Dashboard`.

### Live updates
- `App\Support\SyncVersion::next($locationId)` = the location's `sync` counter (row locked until commit, so versions become visible in order). ### Code style
- Laravel 13 idioms: `#[Fillable]`/`#[Hidden]` on models, `casts()` method, `#[Signature]`/`#[Description]` on commands, invokable controllers for single actions.
- Staff controllers in `App\Http\Controllers\Admin`, validation in `App\Http\Requests\Admin`. Pages in `resources/js/Pages/Admin/...` with `<AdminLayout title="...">`.
- Send only the fields a page needs. Never send whole models.
- Flash `success`/`error` → toast in the layout.
- `Model::preventLazyLoading()` outside production: eager load.
- Run `vendor/bin/pint` and `php artisan test` before finishing a step.
